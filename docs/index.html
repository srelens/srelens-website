Five-minute quick start

  1. Download srelens for your operating system and complete the platform installation.
  2. Launch the app. srelens reads the default kubeconfig and files listed in KUBECONFIG.
  3. Select a context from the searchable first-launch list.
  4. Open Overview to confirm node readiness, workload health, and recent warnings.
  5. Press Cmd/Ctrl-K to navigate to a resource or search across the open cluster.
No account or cluster-side installation

The desktop app connects directly to Kubernetes API servers with the credentials already available through your local kubeconfig.

Terminal interface (srelens-tui)

For operators living in shells or working across SSH connections, srelens-tui provides the full power of srelens inside a native pure-Rust terminal workspace built on kube-rs and ratatui. Completely asynchronous throughout, the interface never blocks on cluster latency.

Fast, keyboard-driven investigation

Instant view switching for opened views, powered by an in-memory Informer cache, live on-demand watch streams, deep Helm and hardware inspection, interactive logs with hanging indent, automatic shell fallback, and embedded AI diagnostics—right in your terminal.

Installation

Install via Homebrew, download direct binaries from Download, or build from source:

# Homebrew (macOS & Linux)
brew install srelens/tap/srelens-tui

# One-line install script (macOS & Linux)
curl -fsSL https://srelens.com/install.sh | bash

# Cargo
cargo install --git https://github.com/srelens/srelens srelens-tui

If you installed via prebuilt binary or the script, update in-place with srelens-tui update (use --check to inspect available updates without installing).

Cluster health & overview (:overview)

Type :overview (or :cluster, :info) from anywhere to get an immediate, high-level control room readout of your connected cluster:

  • Cluster Vitals: Kubernetes server version, API endpoint, reachability status, and context name.
  • Capacity & Readiness: Real-time counts for ready vs. total nodes, and pod distribution broken down by status (Running, Pending, Failed).
  • Aggregate Resource Gauges: Visual progress gauges tracking total CPU cores allocated vs. available, and memory GiB consumed vs. capacity.
  • GPU & Accelerator Awareness: Automatically detects GPU hardware across the cluster and adds dedicated VRAM and card allocation gauges when GPU nodes are present.

Deep node & hardware inspection (:nodes ➔ Enter)

From the node list (:nodes or :no), press Enter on any node (or type :node <name>) to open the deep Node & Hardware Inspector:

  • Hardware & System Specs: Displays CPU architecture, OS image, kernel version, container runtime (e.g. containerd, CRI-O), kubelet version, and internal/external IP addresses.
  • Capacity vs. Allocatable: Direct side-by-side comparison of total vs. allocatable capacity for CPU millicores, Memory MiB, maximum pods, and ephemeral storage.
  • Health Conditions & Taints: Real-time status flags for Ready, MemoryPressure, DiskPressure, PIDPressure, and NetworkUnavailable, alongside active taints, labels, and cordoned/unschedulable state.
  • Pods-per-Node Mapping: Complete table of all pods currently scheduled on the selected node, showing individual pod phases, CPU requests, and memory footprints.
  • Dual Canvas Trend Charts: Real-time canvas line graphs with dynamic Y-axis bounds plotting historical CPU millicores and memory usage trends over time (populated via metrics-server).

GPU nodes & VRAM allocation inspector (:gpuinfo)

For machine learning, AI inference, and compute-heavy clusters, :gpuinfo (or :gpu, :gpus) opens a dedicated, dual-pane accelerator dashboard:

  • GPU Node Fleet (Left Pane): Inspect every GPU-equipped node, detected physical accelerator models (NVIDIA A100, H100, L4, V100, RTX series), installed card counts, total vs. allocated VRAM, and per-node GPU utilization gauges.
  • Workload VRAM Breakdown (Right Pane): See exactly which pods and namespaces are consuming accelerator capacity, their requested physical GPUs or fractional MIG/vGPU slices, and current execution phase.
  • Cluster Totals: Top-level summary tracking total cards installed, cards allocated, aggregate VRAM capacity, and assigned VRAM.

Deep Helm 3 inspection (:helm ➔ Enter)

Type :helm (or :releases) to list all Helm releases across namespaces with chart names, revision numbers, and update times. Press Enter on any release to launch the 5-tab Deep Helm Inspector. Reading releases does not need the helm CLI; rollback calls your local helm:

  • Tab 1 — Overview: Release status, chart name & version, application version, revision count, and timestamp of the last deployment.
  • Tab 2 — Values Diff: Built-in diff engine compares User-Supplied Values against Computed All-Values, chart defaults, or the previous release revision (press m to cycle).
  • Tab 3 — Revisions: Complete historical changelog of every revision. Select any prior revision and press r to perform a safe, one-touch rollback.
  • Tab 4 — Manifest: Full syntax-highlighted rendered Kubernetes YAML manifest produced by the chart templates for that revision.
  • Tab 5 — Notes: View post-installation instructions, endpoints, and release notes rendered by the chart's NOTES.txt.

Embedded SRE AI assistant (:assistant or Tab)

Press Tab or type :assistant (aliases: :ai, :chat) to open the interactive AI assistant drawer directly inside your terminal:

  • Context-Aware Troubleshooting: Ask questions about failing workloads, parse confusing stack traces, diagnose crashloops, or investigate warning event cascades. The assistant receives active cluster context to provide grounded answers.
  • Built-in Slash Commands: Run quick investigation macros like /crashloop, /oom, /rollout, or /endpoints to trigger standardized diagnostic workflows.
  • Multi-Provider & Local LLMs: Configure Anthropic (Claude), OpenAI, Google, or local Ollama models via :ai-settings (or :settings). No proprietary lock-in.
  • High-Density "Caveman Mode": Enable terse, high-information-density output (/caveman) designed specifically for rapid operational debugging with minimal token overhead.
  • Model Context Protocol (MCP) Tools: Integrated with srelens's native MCP tool registry, allowing the AI to safely query cluster APIs and run diagnostic lookups. Tools that change the cluster are blocked in the assistant.

Additional capabilities

  • ArgoCD GitOps & Hub-Spoke (:argo): Inspect applications, sync drift, and health across Hub-and-Spoke cluster topologies with spoke-scoped destination filtering.
  • Node SSH & Out-of-Band Recovery (S on the Nodes view): Open an interactive SSH session to triage unready nodes when the Kubernetes API cannot schedule debug pods. The AI assistant can also read service status and journal logs for services such as kubelet, containerd and rke2-server. Auto-resolves InternalIP and hands authentication to your system ssh, which offers agent identities first and then the standard keys in ~/.ssh/.
  • Headless MCP Server (srelens-tui mcp): Expose 100+ cluster tools to Cursor, Claude, and Gemini over stdio with explicit mutation consent gates.
  • Adaptive On-Demand Watching: An LRU-bounded stream pool watches only the active view and namespace, preventing cluster API overload while streaming live updates to the current screen.
  • First-Class CRD Support: Auto-discovers every CustomResourceDefinition, extracts server-side printer columns (evaluating JSONPaths dynamically), and live-watches CRD instances just like built-in primitives.
  • Engineered Logs Viewer: Long lines wrap with clean hanging indents under the line-number gutter (│ continuation) so numbers stay pinned. Toggle wrap off with w for horizontal scrolling (h/l, 0 to reset). True follow-mode accounts for wrapped visual rows.
  • Instant Shells & Deep Debugging: Press s to drop into a container shell, trying /bin/sh, then bash, through your local kubectl. Open a privileged node shell with s on the Nodes view. MCP clients that launch srelens-tui mcp --allow-destructive can attach ephemeral debug containers to distroless pods (k8s.debugPod). External interactive sessions run on an alternate screen with zero terminal debris on exit.
  • Visual Resource Trees: Press t to view hierarchical ASCII owner-reference trees (Deployments ➔ ReplicaSets ➔ Pods, CRD owners) with live health dots.
  • Port Forwarding Manager: Manage background port-forwards with live byte counters and automatic reconnects (:pf).
  • Reason Rail: Instant event triage and correlation for warning events and crash loops.
  • k9s-Familiar Ergonomics & Theming: : command palette, / filter bar with persistent regex, Space marks for bulk operations, and themes (Catppuccin, Nord, Dracula, Gruvbox, Tokyo Night).

Connect and distinguish clusters

Settings → Contexts manages kubeconfig sources and visual identity. Add files or paste YAML, then assign a display name, short label, logo, and colour without changing the underlying kubeconfig. Contexts with duplicate names remain visible and are prefixed by their source file.

Use the cluster hotbar to switch between open contexts. Local development clusters such as kind, k3d, minikube, and Docker Desktop are grouped separately from remote clusters.

Investigate a workload

  1. Open Workloads → Pods or Deployments and scope the list by namespace.
  2. Select a resource to inspect its Overview, YAML, Events, relationships, restart counts, conditions, and metrics when available.
  3. Open Logs from a pod or workload. Use prev for the previous crashed container instance and ts for timestamps.
  4. Use Shell for an in-pod exec session. For minimal or distroless containers, attach an ephemeral debug container.
  5. Before changing YAML, open Changes to run a dry-run diff. Applying uses server-side apply and asks for confirmation.

Take guarded action

Actions are preflighted against Kubernetes RBAC. An unavailable action is disabled with the reason. Destructive operations—such as delete, evict, drain, or Helm uninstall—require confirmation.

ResourceCommon actions
PodLogs, shell, debug container, edit, forward, evict, delete
WorkloadLogs, edit, scale, rollout restart, delete
NodeCordon, uncordon, drain, node shell
Helm releaseInspect, upgrade, rollback, rendered-diff preview, uninstall

Connect an MCP client

Open Settings → MCP. Run the loopback HTTP server or install the srelens CLI for stdio, then copy the configuration for your MCP client.

{
  "mcpServers": {
    "srelens": {
      "command": "srelens",
      "args": ["--mcp-stdio"]
    }
  }
}

Mutating tools require an explicit "_confirm": true argument. Review tool calls and use Kubernetes RBAC appropriate to the target cluster.

When something fails

  • Check Settings → Application logs for connection, authentication, and unexpected application errors.
  • Use the Toolbox context-health view to identify missing exec-auth plugins or cloud CLIs.
  • If metrics are unavailable, confirm that Metrics Server is installed and accessible with your RBAC.
  • For reproducible bugs, open a GitHub issue with the application log details you can safely share.
