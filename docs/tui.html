Overview

srelens-tui is a native, standalone terminal workspace for Kubernetes. Built with kube-rs and ratatui, it delivers instant view switching for opened views via an in-memory Informer cache, live resource watches, deep Helm 3 values diffs, BGP control plane topology views, and an embedded SRE AI assistant.

Installation & Updates

Homebrew (macOS & Linux)

Install the pre-built binary formula using our official Homebrew tap:

# Tap and install srelens-tui
brew install srelens/tap/srelens-tui

# Launch
srelens-tui

Standalone Install Script (macOS & Linux)

Download and install the latest static binary for your architecture automatically:

curl -fsSL https://srelens.com/install.sh | bash

Cargo (From Source)

cargo install --git https://github.com/srelens/srelens srelens-tui

Updating in-place

If you installed via prebuilt binary or the shell install script, update the binary in-place with a single command: 

# Check for available updates without installing
srelens-tui update --check

# Download and apply update in-place
srelens-tui update

Embedded SRE AI Assistant (:ai or Tab)

The AI assistant drawer provides in-process conversational diagnosis with an estimated token count per reply and direct Kubernetes MCP tool execution.

Supported Providers

Configure your model provider in :ai-settings:

  • Anthropic Claude: default model claude-3-7-sonnet-20250219; any Claude model ID can be set.
  • OpenAI: default model gpt-4o; any chat model ID can be set.
  • Google Gemini: default model gemini-2.5-flash; any Gemini model ID can be set.
  • OpenAI-compatible / Ollama (local): defaults to http://localhost:11434/v1 and llama3.2; point it at any OpenAI-compatible endpoint.

ArgoCD Applications & GitOps Sync (:argo)

Inspect and operate GitOps deployments managed by ArgoCD across multiple target clusters and namespaces.

  • Health & Sync Matrix: Instantly check Synced / OutOfSync states and Healthy / Degraded flags.
  • Repo & Revision: Inspect target git repository URLs, branches, and deployed commit SHAs.
  • Resource Tree Integration: Seamlessly pivot from ArgoCD application to child Kubernetes resources.

ArgoCD Hub & Spoke Architecture

In multi-cluster setups, ArgoCD separates deployment definitions from workload execution:

  • Hub Cluster: The management cluster hosting ArgoCD controllers, repository secrets, and Application CRDs.
  • Spoke Cluster: Target workload clusters where applications run (no ArgoCD controllers installed on spokes).

How srelens-tui Works with Hub & Spoke:

  1. Discover Clusters: Reads cluster registration secrets (labeled argocd.argoproj.io/secret-type: cluster) from the hub cluster.
  2. Match Active Cluster: Matches your current kubeconfig context with Application destinations using server URL or cluster name.
  3. Spoke-Scoped View: Running :argo on a spoke cluster shows only applications deployed to that target. Inspect sync status, health, and trigger reconciliations directly in context.

Configuring ArgoCD Hub Context (:config)

Press : and type :config to open the TUI configuration screen:

  • ArgoCD Hub Context: Select or cycle (h/l or e to edit) the kubeconfig context where your ArgoCD control plane resides.
  • ArgoCD Hub Kubeconfig Path: Set a custom path if your Hub cluster kubeconfig is separate from $KUBECONFIG.
  • Environment Variables: You can also set SRELENS_ARGO_HUB_CONTEXT and SRELENS_ARGO_HUB_KUBECONFIG in your shell environment.

Pod & Workload Operations (:pods)

The pod table provides high-density, real-time monitoring across namespaces with instant filtering and rapid troubleshooting actions.

  • Instant Shells (s): Direct interactive container shells with automatic fallback.
  • Port Forwarding (Shift + F): Quick port forwarding with byte counters.

Deep Helm 3 Values Diff & Rollback (:helm)

Press Enter on any Helm release to launch the 5-tab Helm Inspector. Reading releases does not need the helm CLI; rollback calls your local helm.

  • Three Diff Modes: Compare user values vs. computed values or chart defaults, or diff the current release vs. the prior revision (m cycles the mode).
  • Changelog & History: Inspect release dates, revision status (deployed, superseded, failed).
  • Safe Rollback (r): Select any prior revision and press r to trigger a confirmation-gated rollback.

GPU Fleet & VRAM Allocation Telemetry (:gpuinfo)

View hardware GPU accelerator distribution, physical models, and live VRAM allocation gauges across nodes.

  • Accelerator Models: Automatically detects hardware accelerator classes (H100, A100, L4, T4, Tesla).
  • VRAM Capacity Gauges: Real-time visual progress bars of allocated vs. total GPU memory.
  • Attached Workloads: Drill into training jobs and inference pods bound to specific GPU devices.

BGP Peering & Topology Dashboard (:bgp)

srelens-tui automatically detects cloud-native BGP implementations deployed in your cluster:

  • Cilium BGP Control Plane: Automatically tracks CiliumBGPPeeringPolicy and live peer state.
  • MetalLB: Inspects BGPPeer and IPAddressPool resources.
  • Calico: Discovers BGPPeer resources.
  • Timers & Metrics: Real-time keep-alive timers, hold-down countdowns, and received/advertised route counts.

Engineered Multi-Pod Log Streamer (l)

When inspecting microservices with high-volume JSON logs, standard terminals break line numbers and wrap text chaotically. srelens-tui features engineered log wrapping:

  • Hanging Indents: Wrapped lines wrap cleanly beneath the line number gutter (│ continuation) so line numbers remain readable and aligned.
  • Previous Container Logs (p): View logs from crashed or restarted containers before the fatal exit.
  • Severity Highlighting: Colors error and fatal lines red, warnings yellow, and debug lines dim.

Resource Hierarchy Tree (t)

Press t on any Kubernetes resource to visualize the complete owner-reference hierarchy tree from Ingress down to Pods, plus ConfigMaps, Secrets, PVCs and Nodes.

  • Live Health Indicators: Status dots beside every resource indicate readiness, crashes, or degraded states.
  • Direct Drilldown: Press Enter on any child item in the tree to jump directly to its details.

Shells & Ephemeral Debug Containers

  • Container Shell (s): Drops straight into a container shell, trying /bin/sh, sh, bash and /bin/bash in turn.
  • Ephemeral Debug Containers (MCP): MCP clients that launch srelens-tui mcp --allow-destructive can attach an ephemeral debug container to a distroless pod without restarting it (k8s.debugPod).
  • Privileged Node Shell (s on the Nodes view): Runs kubectl debug node/<name> to open a root shell with the node's host namespaces and filesystem reachable. Requires kubectl on your PATH.

Node SSH & Out-of-Band Diagnostics

When host services like kubelet, containerd, rke2-agent, or k3s fail, the Kubernetes API cannot schedule debug pods or execute commands. srelens-tui provides out-of-band SSH capabilities to triage and recover nodes directly.

Target Resolution & Address Selection

When targeting a node by name, srelens-tui resolves addresses in order of network safety:

  1. InternalIP (default preference for private VPCs and cloud clusters)
  2. ExternalIP (for edge, bare-metal, or public nodes)
  3. Hostname (fallback or direct IP address)

SSH Key Discovery Ladder

srelens-tui hands authentication to your system ssh, which offers agent identities first and then the standard keys in ~/.ssh/:

  1. SSH Agent (SSH_AUTH_SOCK): If an SSH agent is running with loaded keys (ssh-add -l), agent identities are offered first.
  2. Standard Identity Files: Checks standard keys in ~/.ssh/ sequentially:
    • ~/.ssh/id_ed25519
    • ~/.ssh/id_rsa
    • ~/.ssh/id_ecdsa
    • ~/.ssh/id_dsa
  3. Explicit Identity File: Custom key paths can be passed via -i /path/to/key.pem or capability parameters.
  4. User & Port: Defaults to the local system username (or custom target user like ubuntu, ec2-user, or root) on port 22 (or custom -p).

Out-of-Band Service Recovery

  • Interactive Node SSH (S on the Nodes view): Opens an interactive ssh session to the node after you confirm the destination (InternalIP, then ExternalIP).
  • Systemd Status (assistant / MCP, needs --allow-sensitive-reads): Check system service states (systemctl status <service>) without an operational kubelet.
  • Journal Logs (assistant / MCP, needs --allow-sensitive-reads): Retrieve systemd journal logs (journalctl -u <service>, with --since and --grep filters).
  • Guarded Restarts (MCP, needs --allow-destructive): Restart a system service such as kubelet or rke2-server from an MCP client that launches srelens-tui mcp --allow-destructive.

TUI MCP Server (srelens-tui mcp)

srelens-tui includes a headless MCP (Model Context Protocol) server over standard JSON-RPC 2.0 stdio, exposing 100+ cluster tools (Kubernetes, Helm, toolbox and server tools) to AI agents (Cursor, Claude, Gemini, and custom agents).

Safety & Permission Flags

By default, srelens-tui mcp runs in safe read-only mode: queries execute immediately, Secrets are masked, and mutating tools are blocked. Two explicit command-line flags control elevated permissions:

  • --allow-sensitive-reads: Allows the MCP server to run reads that return secret or host-level material, such as Secret contents (k8s.getSecret), node SSH diagnostics, and pod connection data.
  • --allow-destructive: Allows the MCP server to execute mutating/destructive operations (e.g. scaling workloads, rollout restarts, deleting resources, applying manifests, installing plugins). 
# Safe read-only mode (default: secrets masked, mutations blocked)
srelens-tui mcp

# Allow reading sensitive Secret data in plaintext
srelens-tui mcp --allow-sensitive-reads

# Allow mutating and destructive operations
srelens-tui mcp --allow-destructive

# Full access (sensitive reads + destructive mutations)
srelens-tui mcp --allow-sensitive-reads --allow-destructive

CRD Discovery & Evaluated Printer Columns

CustomResourceDefinitions are first-class citizens in srelens-tui:

  • Auto-discovers all CRDs installed across cluster API groups.
  • Evaluates server-side printer column JSONPaths dynamically.
  • Maintains live streaming Informer watches for CRD instances just like built-in primitives.
