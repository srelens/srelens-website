# srelens.com for v0.16.0: the srectl rename and fresh evidence

Status: approved by Devesh on 2026-10-09. This is a PR stacked on PR #12 (`redesign/terminal-native-copy`).

## 1. Why

srelens v0.16.0 shipped on 2026-10-09 as the latest stable release (`srelens-v0.16.0`). It brings three changes the site has to follow.

**The terminal product is now `srectl`.**
- The binary, the crate and the release archives are all `srectl-0.16.0-*`.
- The release still ships `srelens-tui-0.16.0-*` archives, which bridge the old command to `srectl`.
- The Homebrew tap now has only `Formula/srectl.rb`. The site's `brew install srelens/tap/srelens-tui` (15 occurrences) is already broken.

**The site is a release behind.** It pins v0.15.0, and srectl itself now shows "Update: v0.16.0".

**The desktop UI has changed.** v0.16.0 adds a Glass theme, a "Star on GitHub" top-bar button, CPU and memory bars in the Nodes list, row counts in lists and more. Every capture taken from v0.15.0 is now one UI behind ("All new UI images please").

## 2. Decisions

| Question | Decision |
|---|---|
| Scope | Bump to v0.16.0, rename to srectl, and recapture every piece of evidence from v0.16.0. |
| Where | A new branch `release/v0.16.0-srectl` stacked on PR #12's head, opened as its own PR with base `redesign/terminal-native-copy`. |
| Naming | Copy, commands and titles say `srectl`. Each page that used to be found as srelens-tui keeps "formerly srelens-tui" in its `<title>` or meta description, and once in visible copy, so existing searches still land. URLs do not change (`/tui/`, `/docs/tui/`, `/docs/tui.html`). |
| SEO | Every title, meta, H1, heading or JSON-LD change is an exact, commented allowance in the SEO tests. No URL changes, no redirects, no new 404s. Old image files stay published. |

## 3. What changes

### 3.1 Version
- `0.15.0` becomes `0.16.0` everywhere: version labels, `data-version` fallbacks, JSON-LD `softwareVersion`, llms files, and `RELEASE` in `tests/version.test.mjs`.
- Every desktop installer link and every srectl archive link points at a `srelens-v0.16.0` asset that exists. A test checks each linked name against the release's real asset list. The list is committed as a fixture (`tests/fixtures/release-v0.16.0-assets.txt`) from `gh release view srelens-v0.16.0 --json assets`, so tests stay offline.

### 3.2 The srectl rename
- Every user-facing `srelens-tui` becomes `srectl`: product name, commands, flags, archive names, captions, alts and llms files.
  - Exceptions: the "formerly srelens-tui" mentions from §2.
  - Exceptions: historical text, such as the claims-check doc under `docs/superpowers/`, which is not published.
- Homebrew: `brew install srelens/tap/srectl`.
- **`install.sh`.** A pure helper picks the binary name from the version: `srectl` for ≥ 0.16.0 and `srelens-tui` before. The script installs the right archive.
  - The site's install command installs srectl 0.16.0.
  - `--version 0.15.0` still installs srelens-tui 0.15.0.
  - Tested with a test that runs the helper, not by downloading.
- **Pages.** `/tui/` and `/docs/tui/` (and the mirror) name the product srectl. Their `<title>`, meta, og/twitter tags and H1 change with exact allowances, and keep "formerly srelens-tui" in the title or meta.
- **Other pages.** `/download/`, `/`, `/features/`, `/mcp/`, `/docs/`, `/compare/*`, `/faq/` and the llms files update their srelens-tui references. Their titles change only where they name srelens-tui.
- **MCP.** The MCP stdio command everywhere becomes `srectl --mcp-stdio`. Client config snippets use `srectl`.

### 3.3 Fresh evidence from v0.16.0
- **Desktop screenshots.**
  - Make a new read-only srelens worktree at tag `srelens-v0.16.0` (`$SRELENS/.claude/worktrees/site-evidence-v0.16.0`), with `CLAUDE.local.md` copied in, the GitNexus index built (`--index-only`), and `srelens-server` plus `apps/desktop/dist` built.
  - Re-run `scripts/shots/desktop-shots.mjs` for every view that has a page today, in both themes, against `srelens-demo`.
  - Fix `views.mjs` routes and `expect` strings if the next design changed them, test first.
  - Re-review every image and rewrite each alt so it is true of the new image.
  - The Glass theme is not captured. Dark and light stay the two themes.
- **TUI text captures.**
  - Run every `scripts/demo/tui-captures.tsv` row with the published `srectl` 0.16.0 (the installer from §3.2) at 120×32.
  - There should be no update banner, because 0.16.0 is the latest.
  - The hero pods capture gets re-taken too.
  - Figcaptions say `text capture from v0.16.0`.
  - The assistant row stays Devesh's to run with his key. Its README command uses srectl.
- **MCP session.**
  - Recreate the three throwaway kind clusters, re-record with `srectl --mcp-stdio` 0.16.0, re-embed, then delete the clusters.
  - The transcript tests now expect version `0.16.0`.
  - If 0.16.0 trims or reshapes tool results (release notes: "trim tool results and refuse reads too large for the agent"), adapt the renderer test-first. Never hand-edit the transcript.
- **Claims.** Every claim on `/tui/`, `/docs/tui/` and `/features/` that names a key, command, flag or behaviour is re-checked against the v0.16.0 source. Anything that changed is fixed. Anything new in 0.16.0 is not added to the copy unless a capture shows it.

### 3.4 Unchanged
- URLs, the published page set, the shared shell structure and the design system.
- Old image and capture files stay published, so nothing returns 404.

## 4. Safety
- Every host-side `kubectl`/`kind` call uses an isolated kubeconfig under `.superpowers/capture/`. `~/.kube/config` and the user's own `srelens` cluster are never touched.
- The native desktop app never runs; desktop captures use web mode only.
- The srelens product repo is read only. New worktrees carry `CLAUDE.local.md`.
- No API keys are ever handled. Processes are stopped by PID.
- No commit or PR carries attribution lines.

## 5. Tests (written first)
- **Version:** every page and the llms files declare 0.16.0, and every linked release asset name is in the committed v0.16.0 asset list.
- **Rename:**
  - No published page or llms file contains `srelens-tui`, except the allowed "formerly srelens-tui" mentions. Those are counted per page and pinned.
  - Every `brew install` names `srelens/tap/srectl`.
  - Every MCP stdio command is `srectl --mcp-stdio`.
- **`install.sh`:** its version-to-binary helper maps 0.15.0 to srelens-tui and 0.16.0 to srectl, and the default version is 0.16.0.
- **Captures:** every TUI figcaption says v0.16.0, the MCP transcript reports server version 0.16.0, and the existing privacy, update-banner and placement tests still pass.
- **SEO:** the baseline passes with exact allowances only.

## 6. Out of scope
- New feature rows for things new in 0.16.0 (Glass theme, extensions, sidecar SDKs).
- The assistant capture, which needs Devesh's key.
- Re-recording the product tour, which stays hidden.
