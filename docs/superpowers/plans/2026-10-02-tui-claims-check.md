# srelens-tui bindings and claims, checked against v0.15.0

Task 7 of the terminal-native redesign. This file records what the released product does and proposes copy fixes. **No site page is changed by this task.** Tasks 11 and 12 (and the llms edit in Task 23) apply only what Devesh records under `## Decisions`.

**Source of truth.** Git tag `srelens-v0.15.0` (`df6614d0`) in the srelens repo, read with `git show` and `git grep`; the product working tree was not touched. Published assets come from `gh release view srelens-v0.15.0 -R srelens/srelens`. `origin/dev` (105 commits ahead of the tag) was consulted only to tell "not in v0.15.0" from "dev-only".

**Two things were executed, not just read.** The tag's `apps/tui/src/cli.rs`, `commands.rs` and `ai_skills.rs` were compiled verbatim in a scratch crate outside both repos (clap 4.6.6, stubbed theme module) to run the real argument parser, command resolver and slash-command matcher. Their output is quoted in the rows that depend on it (B48, B50, B56, B58, B59, B65, B67, B69, B74).

**Path conventions.**
- Tag paths are relative to `apps/tui/src/` unless they begin with `apps/`, `crates/`, `packages/`, `docs/` or `README.md`: `app.rs:4264` means `apps/tui/src/app.rs:4264` at the tag.
- Page paths are repo-relative, with line numbers from this checkout (branch `redesign/terminal-native`, `7c5b58f`). `docs/tui.html` mirrors `docs/tui/index.html` and is not listed separately.

**Same wording outside the six scanned files.** The brief scoped six files, but a repo-wide grep shows the same claims on other published pages, so a decision recorded below must also be applied there in Tasks 13 to 16: `docs/index.html:117` (3-way diff, C11), `:127` (`/explain`, `/network` per B65 and B67, plus `/logs` and `/playbook`, which do not exist at the tag either), `:136` and `:174` (`Shift + N`, B29), `:137` ("80+", C06), `:141` (bash then sh, C26; `Shift + D` and `Shift + N`, B28 and B29), `:173` (`Shift + D`, B28); `compare/k9s/index.html:6, 16, 17, 20, 21, 28` and `download/index.html:167` ("0ms Informer cache", C02); `docs/index.html:143` ("live throughput metrics", C14); `faq/index.html:64, 199` ("40+ kinds", C07). `mcp/index.html` needs one clarification (row C34): its client configs correctly use `srelens-tui mcp` with no flags, but `mcp/index.html:325` tells readers to launch "the server" with `--mcp-allow-*`, which is the desktop `srelens` spelling and is rejected by `srelens-tui mcp`.

## Already decided

**D1. Windows ARM64 `srelens-tui` download: decided by Devesh and applied in `7c5b58f`** (button removed, card relabelled "x64"; `tui/index.html:600-601` now shows only `srelens-tui-0.15.0-x86_64-pc-windows-msvc.zip`). Evidence that it was right: the v0.15.0 release ships `srelens-tui-0.15.0-x86_64-pc-windows-msvc.zip` and no `aarch64-pc-windows-msvc` archive (full asset list: macOS aarch64 and x86_64 tar.gz; Linux x86_64 and aarch64, each glibc and musl; Windows x86_64 zip only), and `docs/INSTALL.md:76` lists Windows x86-64 only. The desktop release has no Windows ARM64 installer either (`srelens_0.15.0_x64-setup.exe`, `srelens_0.15.0_x64_en-US.msi`). **Residual, not covered by the decision:** `llms.txt:8` and `llms-full.txt:8` still say "Windows (x64 + ARM64)". That needs a text decision: see C09. (Likely source of the error: `README.md:121` in the product repo says the TUI covers "macOS and Windows, on x86-64 and arm64".) Optional clarifier: `tui/index.html:151` says "...and Windows." and could say "Windows (x64)".

**D2. Pods STATUS shows the pod phase (known fact, no decision needed).** In v0.15.0 a crash-looping pod reads `Running`, READY `0/1`, restarts climbing; `CrashLoopBackOff` never appears in the pods list. Evidence: `views/resource_table.rs:311-316` (Pods columns), `views/resource_table.rs:908-911` (`status` resolves to `phase`), `crates/kube/src/pod_overview.rs:31-34` ("a CrashLoopBackOff pod's phase is Running"). **Audit result: no copy in the six files says the TUI pods table shows CrashLoopBackOff.** The nearest hits are accurate: `docs/tui/index.html:256` describes the `/crashloop` AI playbook (`ai_skills.rs:29-41`), and `docs/tui/index.html:158` says `:pods` lists "status, restarts, and node mapping". Rule for later tasks: any prose, caption or alt text describing the TUI pods table must say "Running, 0/1 ready, restarts climbing". The unpublished brainstorm mock `.superpowers/brainstorm/7722-1790934584/content/directions.html:353` shows `CrashLoopBackOff` in a pods STATUS column and must not be ported to the site.

**D3. Version files (known fact, not a discrepancy).** The tag's source version files say 0.14.0 (`Cargo.toml:7`, `[workspace.package]`); the release workflow bumps at build time and the published binary reports v0.15.0.
