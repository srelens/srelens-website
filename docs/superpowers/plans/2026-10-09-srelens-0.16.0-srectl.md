# srelens.com for v0.16.0 (srectl) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move srelens.com to srelens v0.16.0, rename the terminal product to `srectl` everywhere a visitor sees it, and recapture every piece of evidence from v0.16.0.

**Architecture:**
- Install and capture tooling first:
  - the site serves the upstream installer, synced from the v0.16.0 tag;
  - the capture scripts use the repo's own installer and the `srectl` binary.
- Then the version and links, then the copy rename (with exact SEO allowances), then the three evidence recaptures (desktop, TUI, MCP), then a claims re-check.
- Every step is guarded by `node --test`.

**Tech Stack:** static HTML/CSS, Node ≥ 20 ES modules (no npm deps), `node --test`, bash, Docker, kind, the srelens v0.16.0 source (Rust + pnpm) for the web-mode build.

**Spec:** `docs/superpowers/specs/2026-10-09-srelens-0.16.0-srectl-design.md`

## Global Constraints

**Repo and tests**
- Branch `release/v0.16.0-srectl`, stacked on `redesign/terminal-native-copy` (PR #12). Push each commit with `git push` (no force); the controller opens the PR.
- Test command: bare `node --test` from the repo root (never `node --test tests/`). TDD is mandatory: failing test first, see it fail for the right reason, minimal change, green. Paste both runs.
- Conventional Commits, staged by explicit path. NO `Co-Authored-By` trailer and NO "Generated with" footer of any kind.
- Write regex-bearing code with the Write/Edit tools (the Bash tool can halve doubled backslashes inside heredocs/sed). Working files may be CRLF; `read()` normalises.

**Release facts (spec §1)**
- Stable release: tag `srelens-v0.16.0`.
- Terminal binary: `srectl`.
- Archives: `srectl-0.16.0-<target>.tar.gz` (Windows: `.zip`), and `srectl-0.16.0-SHA256SUMS.txt`.
- Homebrew: `brew install srelens/tap/srectl`.
- MCP: `srectl --mcp-stdio`, with `--mcp-allow-destructive` and `--mcp-allow-sensitive-reads`.

**Naming and SEO**
- URLs never change (`/tui/`, `/docs/tui/`, `/docs/tui.html`).
- "formerly srelens-tui" stays in the `<title>` or meta description of `/tui/` and `/docs/tui/` (and the mirror), and once in visible copy on each.
- Every title, meta, H1, heading or JSON-LD change gets an exact, commented allowance (`// Devesh 2026-10-09: v0.16.0 / srectl`).
- Old image and capture files stay published, so there are no new 404s.

**Safety**
- Every host `kubectl`/`kind` call uses an isolated kubeconfig under `.superpowers/capture/` with an explicit `--context`.
- Never read or use `~/.kube/config`. Never touch the kind cluster `srelens`.
- Never run the native srelens desktop app; web mode only.
- The srelens product repo and its worktrees are read only.
- Never handle API keys. Stop processes by PID.
- New git worktrees get the main checkout's `CLAUDE.local.md` copied in, and their GitNexus index built with `gitnexus analyze --index-only` (never plain `analyze`).
