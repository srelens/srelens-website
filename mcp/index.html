A Kubernetes MCP server, built into the app.

The same capability registry that powers the srelens desktop UI is exposed through a built-in MCP (Model Context Protocol) server. Claude Code, Claude Desktop, Cursor, and other MCP clients can investigate and operate your clusters locally, with your kubeconfig credentials, and with explicit confirmation for anything mutating. srelens is the Kubernetes kernel for AI: your agents use it so you don’t have to.

#how · How it works

One registry, two protocols, zero cloud.

  1. 01 — register

    Shared capability registry

    Backend operations such as listing resources, reading logs, and scaling workloads are registered once. The desktop UI and the MCP server both call the same registry.

  2. 02 — connect

    stdio or loopback HTTP

    Clients spawn srelens --mcp-stdio via the installed CLI, or connect to the loopback HTTP server at 127.0.0.1:8765/mcp while the app is open. Nothing listens on external interfaces.

  3. 03 — confirm

    Consent-gated mutations

    Read-only tools just run. Mutating tools require an explicit _confirm: true argument, so an agent has to state its intent before anything changes in a cluster.

#setup · Connect a client

Ready-to-paste config for every AI workspace.

Register srelens-tui mcp or srelens --mcp-stdio with your assistant. Mutating tools require confirmation; read-only diagnostics execute instantly.

Cursor

Add to ~/.cursor/mcp.json (or project .cursor/mcp.json):

{
  "mcpServers": {
    "srelens": {
      "command": "srelens-tui",
      "args": ["mcp"]
    }
  }
}

Claude Desktop

Add to claude_desktop_config.json (Settings → Developer):

{
  "mcpServers": {
    "srelens": {
      "command": "srelens-tui",
      "args": ["mcp"]
    }
  }
}

Claude Code CLI

Register via one-line terminal command:

# register stdio MCP server
$ claude mcp add srelens -- srelens-tui mcp

# or via HTTP server (when enabled)
$ claude mcp add --transport http srelens \
    http://127.0.0.1:8765/mcp

Gemini / Antigravity

Add to your IDE MCP configuration (mcp_config.json):

{
  "mcpServers": {
    "srelens": {
      "command": "srelens-tui",
      "args": ["mcp"]
    }
  }
}

Generic (Any MCP Client)

Standard JSON configuration block accepted by all MCP-compliant tools:

{
  "mcpServers": {
    "srelens": {
      "command": "srelens-tui",
      "args": ["mcp"]
    }
  }
}
/ example

What a gated tool call looks like

An agent asks srelens to scale a deployment. Without _confirm: true the call is rejected with an explanation; with it, the operation runs and reports the result through the same code path as clicking “Scale” in the UI.

mcp · srelens — agent session
→ tools/call scale_workload
{
  "context":   "kind-srelens-demo",
  "kind":      "Deployment",
  "namespace": "payments",
  "name":      "checkout-api",
  "replicas":  6,
  "_confirm":  true
}

✓ explicit confirmation supplied

← ok checkout-api scaled 3 → 6 · 412ms

#answers · Straight answers

What agents can and cannot do.

Can an AI agent break my cluster through srelens?

No. By default, the server runs in safe read-only mode with sensitive data masked. Mutating actions require the server to be launched with --mcp-allow-destructive (--allow-destructive for srelens-tui mcp) and the agent must explicitly provide "_confirm": true in its tool call arguments. Reading plaintext Secrets requires launching with --mcp-allow-sensitive-reads (--allow-sensitive-reads for srelens-tui mcp).

Do my credentials ever leave my machine?

No. srelens connects to clusters directly with your local kubeconfig credentials. The MCP server runs locally, either inside the app or as a local srelens or srelens-tui mcp process, with no srelens cloud relay between an agent and your API servers.

Which MCP clients work with srelens?

Anything that speaks MCP over stdio or HTTP: Claude Code, Claude Desktop, Cursor, Codex, Antigravity, and any client that accepts mcpServers JSON. The settings panel generates the config for each.
