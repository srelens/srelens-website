srelens / mcp

A Kubernetes MCP server, built into the app.

The same capability registry that powers the srelens desktop UI is exposed through a built-in MCP (Model Context Protocol) server. Claude Code, Claude Desktop, Cursor, and other MCP clients can investigate and operate your clusters locally, with your kubeconfig credentials, and with explicit confirmation for anything mutating.

● How it works

One registry, two protocols, zero cloud.

  1. 01 — register

    Shared capability registry

    Backend operations such as listing resources, reading logs, and scaling workloads are registered once. The desktop UI and the MCP server both call the same registry.

  2. 02 — connect

    stdio or loopback HTTP

    Clients spawn srelens --mcp-stdio via the installed CLI, or connect to the loopback HTTP server at 127.0.0.1:8765/mcp while the app is open. Nothing listens on external interfaces.

  3. 03 — confirm

    Consent-gated mutations

    Read-only tools just run. Mutating tools require an explicit _confirm: true argument, so an agent has to state its intent before anything changes in a cluster.

● Connect a client

Two commands to an agent-ready cluster.

Install the srelens CLI from the MCP settings panel, then register srelens with your MCP client. The settings panel generates the exact config for Claude Code, Claude Desktop, Cursor, Codex, and generic mcpServers JSON.

Prefer HTTP? Enable “Run MCP server” in settings and point your client at http://127.0.0.1:8765/mcp. 

# register srelens with Claude Code (stdio)
$ claude mcp add srelens -- srelens --mcp-stdio

# or, with the HTTP server enabled in settings
$ claude mcp add --transport http srelens \
    http://127.0.0.1:8765/mcp
/ example

What a gated tool call looks like

An agent asks srelens to scale a deployment. Without _confirm: true the call is rejected with an explanation; with it, the operation runs and reports the result through the same code path as clicking “Scale” in the UI.

mcp · srelens — agent session
→ tools/call scale_workload
{
  "context":   "kind-srelens-demo",
  "kind":      "Deployment",
  "namespace": "payments",
  "name":      "checkout-api",
  "replicas":  6,
"_confirm":  true
}

✓ explicit confirmation supplied

← ok checkout-api scaled 3 → 6 · 412ms

● Straight answers

What agents can and cannot do.

Can an AI agent break my cluster through srelens?

Mutating tools refuse to run without an explicit _confirm: true argument, and the MCP server only binds to stdio or loopback HTTP on your machine. Agents use the same confirmation-gated code paths as the GUI. Additional MCP security and audit controls are planned during the beta.

Do my credentials ever leave my machine?

No. srelens connects to clusters directly with your local kubeconfig credentials. The MCP server is part of the local app process, with no srelens cloud relay between an agent and your API servers.

Which MCP clients work with srelens?

Anything that speaks MCP over stdio or HTTP: Claude Code, Claude Desktop, Cursor, Codex, Antigravity, and any client that accepts mcpServers JSON. The settings panel generates the config for each.
