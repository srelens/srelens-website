● The reliability loop

From signal to action,
without switching tools.

Incidents don't wait while you juggle terminals, dashboards, and YAML files. srelens keeps the whole investigation in one connected workspace.

  1. 01 — observe

    Observe

    Move through workloads, networking, storage, and access control without changing tools. Every context, one hotbar away. Live watches stream state as it changes.

  2. 02 — diagnose

    Diagnose

    Inspect health, relationships, events, and manifests side by side. Follow logs, exec into containers, and forward ports, all docked next to the evidence.

  3. 03 — act

    Act

    Scale, restart, cordon, drain, or apply an edit right where you found the problem. Destructive actions always ask first. Your error budget stays yours.

● The workspace in detail

The whole investigation, in one window.

Every image on this page is a real capture of srelens running against a live multi-node kind cluster, not a mockup.

/ 01

Live metrics beside the manifest

Select a pod and the drawer shows CPU and memory streamed from the Kubernetes Metrics Server, next to properties, conditions, events, and the full YAML. No tab-hopping between dashboards and manifests.

Explore all features →

/ 02

Logs, shells & forwards in the dock

Exec into containers with a full terminal, follow logs from pods or whole workloads, and manage port forwards. Everything stays docked beside the resource you are debugging, even when you switch tabs.

/ 03

Backend capabilities available through MCP

One shared registry powers the desktop application and the built-in MCP server. Supported backend capabilities are available as MCP tools over stdio or loopback HTTP, with ready-to-paste config for Claude Code, Claude Desktop, Cursor, and other MCP clients. Mutating tools require an explicit _confirm: true argument before they run.

● Feature surface

Everything an operator reaches for.

resources

40+ resource kinds

Workloads, config, storage, networking, RBAC, admission, and autoscaling. Filter by namespace with state remembered per cluster.

live data

Streaming watches

Tables update in place as the cluster changes, backed by shared kube-rs watch streams instead of polling.

speed

Command palette

Hit ⌘K to jump to any resource in any cluster using global search with deep links into detail views.

ecosystem

Helm & CRDs

Inspect Helm releases and browse custom resources grouped by API group. CRDs are first-class citizens.

metrics

Cluster usage

CPU and memory for nodes and pods via metrics-server provide health at a glance.

node ops

Safe cluster actions

Scale, rollout-restart, evict, cordon, and drain. Every destructive action is flagged and confirmation-gated.

contexts

Multi-kubeconfig

Add kubeconfig files or paste one in. Context profiles, custom ordering, and a hotbar for the clusters you live in.

tabs

Browser-style tabs

Each tab is a cluster and resource view. Close others or close to the right without losing investigation state.

privacy

Local-first

Talks directly to your API servers with your kubeconfig credentials. No cloud service in between.

● Architecture

A familiar workflow, rebuilt in Rust.

srelens follows a familiar Kubernetes desktop workflow while using Tauri v2 and a pure-Rust core. It is independently developed and is not affiliated with Mirantis Lens or the Freelens project. See the full comparison →

Architecture choice srelens approach What it means
Rendering OS system WebView via Tauri v2 No bundled Chromium in the application package
Core runtime Pure Rust using kube-rs and tokio No Node.js in the core application runtime
Cluster access Direct to the Kubernetes API server Uses local kubeconfig credentials without an intermediary srelens cloud service
AI agents Built-in MCP server Supported backend capabilities are available to MCP-capable clients
Project model Open source under the MIT license Code, releases, issues, and roadmap are public on GitHub

● Hacking on it?

Or run it from source.

Prefer to build it yourself or want to contribute? The app builds and runs with the standard Rust and pnpm toolchains.

# clone and run the desktop app
$ git clone https://github.com/srelens/srelens
$ cd srelens
$ pnpm install
$ pnpm dev

● FAQ

Questions operators ask.

What is srelens?

srelens is a Kubernetes desktop workspace — a native GUI app for browsing, inspecting, and operating Kubernetes clusters. It reads the contexts in your local kubeconfig and gives you resource browsing across 40+ kinds, live watches, log streaming, in-pod terminals, port forwarding, Helm release views, and a schema-aware YAML editor, all in one window. It's built on Tauri v2 with a pure-Rust core.

How is srelens different from Lens or Freelens?

srelens uses Tauri v2 with a pure-Rust core and connects directly to Kubernetes API servers through kube-rs. It follows a familiar Kubernetes desktop workflow while providing local-first operation and MCP access for supported backend capabilities. srelens is independently developed and is not affiliated with Mirantis Lens or the Freelens project. Read the full comparison.

Where do my cluster credentials go?

Nowhere. srelens runs entirely on your machine and connects to clusters directly using the credentials in your local kubeconfig files. There's no intermediary cloud service between the app and your API servers.
