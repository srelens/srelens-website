The capability registry

Every registered backend operation carries an identifier, JSON input and output schemas, safety annotations, and an asynchronous handler. One registration becomes available to both the Tauri command bridge and the MCP tool surface.

A completeness test in the application repository asserts that registered capabilities and the MCP tool list remain aligned. This makes the shared surface testable rather than relying on documentation convention.

Streaming operations

Resource watches, pod exec sessions, log tails, and port forwards do not fit a request/response call. Dedicated start, stop, input, and resize commands push updates through Tauri events while the frontend maintains the visible session.

Local Kubernetes access

The Rust backend resolves kubeconfig contexts and constructs kube-rs clients. Cluster browsing, RBAC checks, schema discovery, metrics, Helm inspection, and operational actions remain local to the application process and the target Kubernetes API server.

Why Tauri

Tauri uses the operating system WebView for the React interface while native operations stay in Rust. srelens does not bundle an Electron runtime. The transport shim is the only frontend module that imports the Tauri API, keeping application state and UI logic testable outside the desktop shell.
