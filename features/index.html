Every feature, shown with real screenshots.

Each capture on this page is srelens connected to a live three-node kind cluster running real workloads: deployments, a StatefulSet, CronJobs, and one deliberately crash-looping pod.

/ 01

A live pods table, not a refresh button

Filter by namespace and watch phase, readiness, restarts, CPU, and memory update in place as the cluster changes through kube-rs watches. The crash-looping legacy-adapter pod shows its restart count climbing in real time.

/ 02

Metrics and manifest, side by side

The detail drawer streams CPU and memory from the Kubernetes Metrics Server next to properties, conditions, controller references, and events. See the whole picture of a pod without leaving the table.

/ 03

Schema-aware YAML editing

Open the YAML tab and edit the live manifest with syntax highlighting, line numbers, and apply/reset, driven by your cluster's own OpenAPI schema with CRDs included.

/ 04

Exec into any container

A full interactive terminal, docked in the workspace. Here it resolves a headless Redis service with nslookup from inside a worker pod and receives DNS answers straight from the cluster.

/ 05

Logs that follow the investigation

Stream logs from any pod or whole workload with container filtering and search, docked beside the resource and still running when you switch tabs to check the nodes.

/ 06

Nodes with real usage numbers

Roles, taints, versions, and live CPU/memory from metrics-server for every node. Cordon, drain, and evict are one action away and always confirmation-gated.

/ 07

Cluster health at a glance

The overview turns live API data into a compact operational summary: node readiness, pod health, workload and service counts, namespace coverage, and the warnings worth investigating first.

/ 08

Namespaces without losing the cluster view

See every namespace, its status, age, labels, and live resource totals in one table, then open a namespace directly to continue the investigation with the right scope.

/ 09

Events are an investigation surface

Search and filter Kubernetes events across namespaces, sort by severity and time, and jump from a warning to the object that emitted it instead of reconstructing the trail from CLI output.

/ 10

Workloads with rollout context

Deployments expose desired and available replicas, update strategy, images, selectors, age, and live usage. Scale or restart a rollout from the same view, with confirmation before the action runs.

/ 11

Services and endpoints in context

Inspect service type, cluster IP, ports, selectors, and endpoint readiness alongside the workloads they route to. Networking stays part of the same tabbed workspace.

/ 12

Port forwards, managed centrally

Create, inspect, copy, and stop forwards for resources across the open cluster. The dedicated view keeps active tunnels visible instead of burying them in background terminal processes.

/ 13

Helm releases in the same workspace

List and inspect releases, then install, upgrade, roll back, or uninstall with values and rendered-diff context—without switching to a separate Helm dashboard.

/ 14

Built-in MCP for AI agents

Start the loopback MCP server, install the stdio CLI, and copy client configuration from Settings. The same Rust capability registry powers the desktop and agent surfaces, with explicit confirmation required for mutations.

/ 15

Destructive actions ask first

Deleting a pod opens a confirmation that names the pod and its namespace and shows the equivalent kubectl command. Nothing changes in the cluster until you confirm.

/ 16

See what a Helm upgrade changed

Select a release and the side pane renders the manifest diff between its current revision and the one before, with Roll back and the values editor beside it.

/ 17

Trace how traffic reaches a workload

Topology lays a namespace out by hops from where traffic enters, from Service to workload to whatever it calls. Dependencies read from environment variables, arguments and ConfigMaps are drawn as declared, apart from routes, and selecting a node lists what it reaches.
